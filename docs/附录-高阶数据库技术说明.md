## 2. DB-Tech-01 存储过程

### 2.1 sp_enroll_course

**业务场景**：学生选课，封装全部校验与写入逻辑。

**参数设计**：

| 参数 | 方向 | 类型 | 说明 |
|------|------|------|------|
| p_student_no | IN | VARCHAR(20) | 学号 |
| p_offering_id | IN | BIGINT | 开课计划 ID |
| p_result | OUT | INT | 0=成功，非 0=错误码 |
| p_message | OUT | VARCHAR(200) | 结果描述 |

**内部逻辑概要**：

1. `START TRANSACTION`
2. `SELECT * FROM course_offering WHERE id = p_offering_id FOR UPDATE`
3. 校验：开课计划状态 = 开放选课
4. 校验：enrolled_count < capacity
5. 校验：学生学籍 = 在读
6. 校验：不存在重复 enrollment
7. 校验：先修课程均已通过
8. 校验：上课时间无冲突（简化字符串匹配或时间段表）
9. `INSERT INTO enrollment (...)`
10. `COMMIT`（enrolled_count 由触发器维护）

**错误码建议**：

| p_result | 含义 |
|----------|------|
| 0 | 成功 |
| 1001 | 课程已满 |
| 1002 | 重复选课 |
| 1003 | 先修课未通过 |
| 1004 | 时间冲突 |
| 1005 | 学籍不允许 |

**验证方法**：

- 应用层 `CALL sp_enroll_course('2024001', 1001, @r, @m); SELECT @r, @m;`
- 模拟满员课程，确认返回 1001

**报告素材**：存储过程源码、CALL 示例、成功/失败截图

### 2.2 sp_batch_save_grades

**业务场景**：教师一次性保存某班全部学生成绩。

**参数设计**：

| 参数 | 方向 | 说明 |
|------|------|------|
| p_offering_id | IN | 开课计划 ID |
| p_grades_json | IN | JSON 数组 `[{enrollmentId, usual, final}, ...]` |
| p_result | OUT | 0=成功 |
| p_count | OUT | 成功写入条数 |

**内部逻辑概要**：

1. 解析 JSON 数组
2. 逐条校验分数 0–100、未锁定
3. 计算 total_score = usual * 0.3 + final * 0.7
4. INSERT 或 UPDATE grade
5. 返回写入条数

**报告素材**：JSON 参数示例、批量保存前后 grade 表对比

## 3. DB-Tech-02 触发器

### 3.1 选课人数同步

| 触发器 | 时机 | 动作 |
|--------|------|------|
| trg_enrollment_after_insert | AFTER INSERT ON enrollment | enrolled_count + 1 |
| trg_enrollment_after_delete | AFTER DELETE ON enrollment | enrolled_count - 1 |

**验证**：选课前记录 enrolled_count，选课后 +1，退课后 -1。

### 3.2 成绩变更日志

| 触发器 | 时机 | 动作 |
|--------|------|------|
| trg_grade_after_update | AFTER UPDATE ON grade | INSERT grade_change_log（旧值/新值 JSON） |

**验证**：管理员修改已提交成绩，grade_change_log 新增一条记录。

**报告素材**：触发器源码、操作前后表数据对比

## 4. DB-Tech-03 视图

### 4.1 v_student_grade_summary

**用途**：学生成绩一览，供 RPT-05 与 UC-07 使用。

**包含字段（示例）**：学号、姓名、专业、课程名、学期、平时、期末、总评、考试类型、学分

**SQL 思路**：student JOIN enrollment JOIN course_offering JOIN course JOIN semester LEFT JOIN grade

### 4.2 v_student_public

**用途**：对外展示学生列表，隐藏身份证密文。

**脱敏规则**：

```sql
CONCAT(LEFT(id_card_plain, 3), '***********', RIGHT(id_card_plain, 4)) AS id_card_masked
```

> 实际实现中，若库内仅存密文，需在视图中 DECRYPT 后再脱敏，或应用层解密后脱敏；需求阶段约定「界面脱敏」即可。

**验证**：db_student 用户 SELECT v_student_public 成功，直接 SELECT student.id_card_enc 被拒绝或无权限。

## 5. DB-Tech-04 索引优化

### 5.1 建议索引

| 表 | 索引 | 类型 | 服务查询 |
|----|------|------|----------|
| student | (student_no) | UNIQUE | 按学号精确查 |
| student | (college_id, major_id, status) | 复合 | 院系学生列表 |
| enrollment | (student_id, offering_id) | UNIQUE | 防重复、JOIN |
| enrollment | (offering_id) | 普通 | 按班查选课名单 |
| grade | (offering_id) | 普通 | 按班查成绩 |
| grade | (enrollment_id) | UNIQUE | 1:1 关联 |

### 5.2 性能对比实验

1. 准备 ≥5000 条 enrollment、grade 测试数据
2. 执行典型查询（如按 offering_id 查成绩 JOIN student）
3. **无索引**：EXPLAIN + `SET profiling=1` 计时
4. **有索引**：重复上述步骤
5. 记录 type、rows、Extra、Duration 对比

**报告素材**：EXPLAIN 截图对比表、计时结果表

## 6. DB-Tech-05 事务与并发控制

### 6.1 业务场景

热门课程剩余 1 个名额，10 个学生同时点击选课，最终仅 1 人成功，其余收到「已满员」提示。

### 6.2 技术要点

| 项 | 选择 | 理由 |
|----|------|------|
| 隔离级别 | REPEATABLE READ | MySQL 默认，配合 InnoDB 行锁 |
| 锁机制 | SELECT ... FOR UPDATE | 锁定 course_offering 行 |
| 死锁处理 | 捕获 1213 错误，重试 ≤3 次 | 避免用户看到系统错误 |

### 6.3 验证脚本思路

- 使用 JMeter、多线程 Java 程序或 Shell 并发 CALL sp_enroll_course
- 断言：成功数 + 原 enrolled_count = capacity
- 断言：无 enrolled_count > capacity 的情况

**报告素材**：并发测试配置、最终 enrolled_count 截图、失败请求提示截图

## 7. DB-Tech-06 窗口函数

### 7.1 专业内成绩排名

```sql
SELECT student_no, name, course_name, total_score,
       RANK() OVER (PARTITION BY major_id ORDER BY total_score DESC) AS major_rank
FROM v_student_grade_summary
WHERE semester_id = ?;
```

### 7.2 累计获得学分

```sql
SELECT student_no, semester_code, credit,
       SUM(credit) OVER (
         PARTITION BY student_id
         ORDER BY semester_id
         ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW
       ) AS cumulative_credit
FROM v_student_grade_summary
WHERE total_score >= 60;
```

**验证**：手工计算 2–3 名学生排名与累计学分，与 SQL 结果比对。

**报告素材**：SQL 与结果截图、排名逻辑说明

## 10. DB-Tech-09 审计日志

### 10.1 audit_log 表结构要点

| 字段 | 说明 |
|------|------|
| table_name | 被操作表名 |
| operation | INSERT / UPDATE / DELETE |
| record_id | 主键值 |
| old_value | JSON，UPDATE/DELETE 时有值 |
| new_value | JSON，INSERT/UPDATE 时有值 |
| operator | 当前数据库用户或应用传入的操作者 |
| operate_time | 操作时间 |
| academic_year | 分区键 |

### 10.2 通用审计触发器思路

为 student、grade、enrollment 各建 AFTER INSERT/UPDATE/DELETE 触发器，统一 INSERT INTO audit_log。

### 10.3 验证

1. 管理员修改某学生成绩
2. 查询 audit_log WHERE table_name='grade' AND record_id=?
3. 确认 old_value、new_value 包含修改前后分数

**报告素材**：一条完整审计记录截图、触发器源码

## 11. DB-Tech-10 数据加密

### 11.1 存储方案

| 字段 | 说明 |
|------|------|
| id_card_enc | AES_ENCRYPT(明文, 密钥) 二进制 |
| id_card_hash | SHA2(明文, 256) 用于精确匹配（可选） |

### 11.2 密钥管理

- 密钥存放于应用配置文件或环境变量，**不写入数据库**
- 数据库内不存储明文身份证号

### 11.3 验证

1. `SELECT id_card_enc FROM student WHERE student_no='2024001'` → 显示二进制密文
2. 应用解密后界面显示 `110***********1234`
3. 按学号查询不受影响（不依赖身份证明文索引）

**报告素材**：密文 hex 截图、脱敏界面截图、加解密流程说明

## 12. DB-Tech-11 备份恢复（可选）

### 12.1 备份策略

| 类型 | 频率 | 工具 |
|------|------|------|
| 全量备份 | 每日凌晨 | mysqldump |

## 13. DB-Tech-12 全文检索（可选）

### 13.1 业务场景

课程名称关键字搜索，如搜索「数据库」匹配「数据库原理」「数据库系统概论」。

### 13.2 实现

```sql
ALTER TABLE course ADD FULLTEXT INDEX ft_course_name (name);

SELECT * FROM course
WHERE MATCH(name) AGAINST('数据库' IN NATURAL LANGUAGE MODE);
```

### 13.3 性能对比

- 对比 `LIKE '%数据库%'` 与 FULLTEXT 在 ≥1000 条课程下的 EXPLAIN 与耗时
